# Orden espacial confirmado por el operador

La fila de mobiliario se lee **de derecha hacia la izquierda**: mesa negra de reuniones → mesa de trabajo A → mesa de trabajo B → mesa de trabajo C → mesa de trabajo D. La mesa negra no cuenta como una de las cuatro mesas de trabajo.

- A y B: las **dos primeras mesas de trabajo** después de la mesa negra; son las dos que ya tienen anotaciones originales. Cada una se reserva como oficina privada completa.
- C y D: las **dos mesas siguientes**, visibles sin anotaciones originales; son mesas públicas de puestos individuales.
- No existe mesa E, ni una mesa C de staff.

Las anotaciones son referencias internas de calibración, no elementos que deban mostrarse en la interfaz. Esta correspondencia semántica queda confirmada por el operador; las coordenadas exactas de cada asiento todavía deben determinarse con selección/picking en la geometría original, sin inventarlas. La presencia de cuatro mesas no es un bloqueo para implementar el inventario. Los personajes deben ser visibles en la demo y vinculados a entidades Core; no se aceptan solo tests de archivos GLB.

Estado: decisión documentada, cambios de inventario y UI pendientes de implementación y pruebas.
