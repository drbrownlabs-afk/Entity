# Investigación aplicada: Blender → glTF → PlayCanvas

Fuentes oficiales consultadas el 2026-11-08. El maestro aprobado no se modifica; las adaptaciones son exclusivamente de exportación y del visor nuevo.

| Fuente | Hallazgo y aplicación |
|---|---|
| [PlayCanvas: rendimiento](https://developer.playcanvas.com/user-manual/optimization/guidelines/) | Reducir draw calls, sombras y superficies alpha blended; limitar postprocesado y resolución por dispositivo. Implementadas instancias GPU por celda, batching del resto y perfiles de coste. La guía orienta 100–200 draw calls para móviles de gama baja; es una referencia, no un rendimiento ya demostrado aquí. |
| [PlayCanvas: instancias](https://developer.playcanvas.com/user-manual/graphics/advanced-rendering/hardware-instancing/) | Matrices en VertexBuffer y MeshInstance.setInstancing. Las instancias necesitan agrupación espacial para culling útil; no basta con compartir un mesh en GLB. Se mantienen nodos semánticos originales para selección e integración posterior. |
| [Khronos: EXT_mesh_gpu_instancing](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Vendor/EXT_mesh_gpu_instancing/README.md) | Distingue data instancing y GPU instancing; la conversión puede perder jerarquías. Se conserva data instancing en GLB, y el adaptador construye GPU instancing sin borrar IDs. |
| [PlayCanvas: compresión de texturas](https://developer.playcanvas.com/user-manual/optimization/texture-compression/) | JPEG/WebP pequeños no garantizan poca VRAM. Basis permite transcodificar al formato GPU disponible. Se usa KTX2/UASTC con mipmaps y Zstd, identificando normales y datos lineales. |
| [Khronos: KHR_texture_basisu](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_texture_basisu/README.md) | UASTC para detalle/normal, espacios lineal/sRGB correctos y pirámide completa de mipmaps. La salida conserva resolución fuente; el formato final GPU depende del dispositivo. |
| [PlayCanvas: Draco](https://developer.playcanvas.com/tutorials/loading-draco-compressed-glbs/) y [KHR_draco_mesh_compression](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_draco_mesh_compression/README.md) | Compresión de geometría con decodificador local WASM. Se elige Draco compatible con el parser instalado de PlayCanvas 2.23.3. Meshopt no se da por soportado por inferencia: no figura en ese parser. |
| [PlayCanvas: lightmapping](https://developer.playcanvas.com/user-manual/graphics/lighting/lightmapping/) | Lightmaps externas, AO y box-projected IBL son técnicas oficiales para archviz. Se hornea oclusión de contacto estática, sin hojas de puerta móviles ni iluminación artificial conmutable. No se congela la iluminación que debe responder al reloj y a cada interruptor. |
| [PlayCanvas: environment lighting](https://developer.playcanvas.com/user-manual/graphics/physical-rendering/environment-lighting/) | Atlas prefiltrado para reflexión rugosa y luz ambiental, cubemap para reflejo nítido; refraction dinámica necesita scene color. El visor carga HDRI, genera atlas y habilita sceneColorMap. Reflejos interiores locales requieren probes adicionales; no se presentan los reflejos de un HDRI como reflejos exactos de la sala. |
| [PlayCanvas: carga](https://developer.playcanvas.com/user-manual/optimization/load-time/) | Medir red, JS/JSON, texturas y arranque; evitar assets duplicados y servir gzip/Brotli. La referencia de carga inferior a 5 s es objetivo, no resultado declarado. |
| Exportador oficial Blender 4.3.2 instalado, `io_scene_gltf2/blender/exp/material/` | Los nodos de Cycles no son intercambiables con glTF. Materiales procedurales se muestrean en atlas albedo/normal; vidrio se expresa por transmisión/IOR; vegetación por PBR de doble cara y máscara alpha. Se preservan los UV originales de assets fotográficos. |

Documentación PlayCanvas obtenida de su repositorio oficial `playcanvas/developer.playcanvas.com`, revisión `323d97fe61e7d02b18d01d2c561dba89f9d02dc2`. El código de runtime se contrasta además con el SDK npm fijado `playcanvas@2.23.3`, no únicamente con documentación más reciente.

El criterio de aceptación combina integridad geométrica/semántica, validación glTF, importación real, comparación visual y mediciones. La emulación móvil y SwiftShader permiten probar interfaz y funcionamiento, pero no sustituyen Chrome Android/Safari iOS sobre hardware físico. Este entorno no tiene un teléfono físico conectado: esa parte del gate permanece abierta hasta obtener mediciones reales.

## Corrección vinculante tras comparación visual

El primer resultado fue RECHAZADO expresamente por el operador. No se acepta priorizar descarga/resolución sobre fidelidad. Se incorporan techos y remates ocultos para overview, recolor UV de macetas, AgX analítico de three.js (MIT), luces LTC con formas/dimensiones de Blender, lightmaps HDR ambientales y una base HDR de indirecta artificial con ganancias dinámicas por circuito. El aporte directo continúa individual; la indirecta artificial por circuito es una aproximación espacial promedio, declarada, y alcanza cero en OFF. Se integran reflejos locales HDR con box projection mediante el mecanismo oficial cubemap-renderer/reflection-box; captura actualizada según estado, no una fotografía fija independiente de los interruptores.

Perfiles corregidos: misma resolución de render (escala 1) y mapas fuente en todos los perfiles; ajustes de sombras/MSAA/SSAO. Sin reducción automática agresiva de resolución. Objetivo de estabilidad aproximado: 30 FPS en el móvil objetivo, pendiente de prueba física. Se admiten cargas mayores para preservar fidelidad. Fuente de ejemplo oficial PlayCanvas `bd16296a1b40778dd74ebdc0e995bbb1702e58e5` y utilitario npm 2.23.3, contrastados con API instalada.
